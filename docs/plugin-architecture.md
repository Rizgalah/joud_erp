# بنية التوصيل في قلب النظام (Joud Core Plugin Architecture)

"قلب النظام" (Joud Core) مصمم للاتصال والتكامل مع "برنامج المحاسبة" (وغيره من الأنظمة الفرعية) بطريقة ديناميكية ومرنة. يعتمد النظام على معمارية **الإضافات (Plugins/Modules)** للاتصال بالبرامج الأخرى.

## 1. اكتشاف تلقائي للإضافات (Auto-Discovery)
يحتوي النظام الأساسي على صنف يسمى `PluginRegistry` يعمل عند بدء تشغيل التطبيق. يستخدم هذا الصنف آلية **Java ServiceLoader (SPI)** للبحث التلقائي عن أي وحدات أو برامج فرعية (مثل `joud-accounting`) مرتبطة بالنظام دون الحاجة لبرمجتها بشكل صلب (Hardcoded) داخل القلب.

## 2. إدارة الاعتماديات (Dependency Management)
عندما يكتشف القلب وجود برنامج المحاسبة، يقوم أولاً بالتحقق مما إذا كانت جميع المتطلبات والاعتماديات التي يحتاجها هذا البرنامج متوفرة (`canActivate`). إذا كان كل شيء سليماً، يقوم بتفعيله.

## 3. الدمج الكامل في الواجهة والصلاحيات
بمجرد نجاح الاتصال، يقوم "قلب النظام" بسحب ودمج كل مكونات برنامج المحاسبة تلقائياً:
* **القوائم (Menus):** يدمج شاشات المحاسبة في القائمة الرئيسية للنظام (`getAllMenuItems`).
* **التقارير (Reports):** يضيف تقارير المحاسبة إلى "ماكنة التقارير" المركزية (`getAllReports`).
* **الصلاحيات والأمان (Permissions):** يسحب صلاحيات المحاسبة ليتم إدارتها من خلال نظام الأمان المركزي الموجود في القلب (`getAllPermissions`).

### الخلاصة
**قلب النظام (Joud Core)** يعمل كمنصة حاضنة (Host) تكتشف وتتصل بـ **البرامج الفرعية كبرنامج المحاسبة (Joud Accounting)** كـ "وحدة قابس" (Plugin)، مما يجعل النظام قابلاً للتوسع بسهولة شديدة.
